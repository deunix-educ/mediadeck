# CLAUDE.md — MediaDeck

Contexte pour reprendre le projet avec Claude Code (VSCodium). À lire avant toute modification.

## Objectif

Télécommande web pour un **PC multimédia Linux** (Debian / LMDE, KDE Plasma), utilisée depuis une
**tablette Android** posée à côté. Le PC exécute un pont Python ; la tablette n'a besoin que d'un
navigateur en plein écran. KDE Connect a été écarté : MPRIS, PipeWire, uinput et logind sont pilotés
directement, ce qui donne plus de contrôle et une interface libre.

## Conventions (obligatoires)

- Code, identifiants et messages de log/erreur en **anglais** ; commentaires et docstrings en **français**.
- Indentation **4 espaces** partout (Python, JS, CSS, HTML, JSON, TOML). Seule exception : les recettes du Makefile (tabulations).
- JavaScript : **classes** ES, modules natifs, aucune dépendance ni étape de build.
- Python ≥ 3.11, typé ; **pyright** doit rester à 0 erreur (`make lint`).
- Documentation double : `README.md` (fr) et `README-EN.md` (en), à garder synchronisés.
- Toutes les opérations système passent par le **Makefile**.
- `.gitignore` doit exclure tout secret ; `config.toml` contient le jeton et ne doit jamais être commité.
- Fins de ligne LF (`.gitattributes`, `.editorconfig`).

## Commandes

```bash
make install      # .venv + dépendances (+ pyright)
make config       # ~/.config/mediadeck/config.toml (mode 600) + jeton aléatoire
make dev          # serveur au premier plan, logs debug
make lint test    # pyright + unittest
make test-ui      # interface dans Chromium (tests/test_ui*.py) ; ignoré sans chromium (`apt install chromium`)
make test-integration  # seulement le scénario complet (tests/test_integration.py ; déjà inclus dans `make test`)
make cert         # HTTPS local (CA privée + certificat), à lancer après `make config`
make http-on/off  # port HTTP en clair à côté du HTTPS
make url          # URL tablette + QR code
make qr           # page locale avec les QR codes en grand
make uinput       # règle udev uaccess (sudo)
make service-install / status / logs
```

## Architecture

```
mediadeck/
├── __main__.py   CLI : --config, --check, --url, -v ; lance web.run_app
├── config.py     TOML → dataclasses gelées ; validation stricte ; refuse un fichier lisible par group/other
├── server.py     aiohttp : /, /static/*, /ws (jeton), /art (jeton) ; diffusion d'état anti-rebond 100 ms + toutes les 10 s ;
│                 open_sites()/serve() : port principal (HTTPS si TLS) + port HTTP en clair facultatif (`http_port`)
├── mpris.py      MprisManager : découverte via NameOwnerChanged, PropertiesChanged + Seeked ; Player.execute() ; Player.close() désabonne les signaux ; interfaces décrites en statique (_INTROSPECTION) ; rattachement avec nouvelles tentatives
├── audio.py      AudioManager : `pactl -f json list sinks`, `pactl subscribe` (relancé si mort), set-sink-*
├── input.py      VirtualInput : 2 périphériques uinput (clavier + pointeur), touches en liste blanche + TYPING_KEYS (saisie)
├── keymap.py     disposition réelle (kxkbrc / setxkbmap / D-Bus KDE) -> table keysym -> frappes (libxkbcommon via ctypes)
├── text.py       TextTyper : texte -> frappes uinput, verrou, relâchement garanti, 500 caractères max
├── system.py     SystemControl : logind (suspend/reboot/poweroff), ScreenSaver.Lock, lancement des lanceurs
├── launchers.py  LauncherStore (SQLite), validation, build_argv(), applications .desktop, navigateurs
├── admin.py      API REST /api/* des lanceurs et des lecteurs de fichiers (jeton en en-tête Authorization: Bearer)
├── media.py      MediaLibrary : dossiers autorisés, parcours sûr (.., liens, cachés, extensions), recherche, enrich() MPRIS ; MediaApi (/api/media, /api/media/search, /thumb)
├── thumbs.py     Thumbnailer : miniatures et images d'illustration par ffmpeg (images, image d'une vidéo, pochette d'un son), cache disque
├── restapi.py    json_response / error_response / bearer_authorized, partagés par admin.py et media.py
├── network.py    interfaces réseau (ioctl SIOCGIFADDR, /sys/class/net) : `advertised_warning()` signale une adresse annoncée portée par une interface virtuelle
├── qrpage.py     page HTML locale des QR codes (`make qr`) : qrencode -t SVG, images en data: URI, écrite en 600 dans $XDG_RUNTIME_DIR
├── tls.py        HTTPS local : CA privée + certificat serveur (CLI openssl), contexte SSL, enable_tls()
└── web/
    ├── index.html        sprite SVG + 5 panneaux (player + audio, media, remote, launchers, system)
    ├── admin.html        page /admin : liste + dialogue d'édition des lanceurs
    └── static/common.js  Storage, I18n(messages), $ : partagés par app.js et admin.js
        static/admin.js   Api, AppPicker, LauncherList, LauncherForm, OpenerList, OpenerForm, AdminPage ; static/admin.css
        static/app.js     Throttle, Connection, PlayerPanel, AudioPanel,
                          Touchpad, RemotePanel, HoldButton, LauncherPanel, MediaPanel, SystemPanel, Toast, Tabs, ScreenKeeper, App
```

Tout tourne dans **une seule boucle asyncio**. Le service doit s'exécuter **dans la session graphique**
(service `systemd --user`, `WantedBy=graphical-session.target`) pour accéder au bus D-Bus de session et à PipeWire.

## Protocole WebSocket

Connexion : `ws://host:port/ws?token=…` (HTTP 401 sinon). Messages JSON ≤ 4 Ko.

Client → serveur :

```json
{"domain": "player", "action": "play_pause|play|pause|stop|next|previous|seek|set_position|set_volume|shuffle|loop|raise", "player": "<bus name>", "value": …}
{"domain": "audio",  "action": "set_volume|toggle_mute|set_default", "sink": "<name|null=défaut>", "value": 0.0-max_volume}
{"domain": "input",  "action": "key", "key": "<nom de KEY_NAMES>"}
{"domain": "input",  "action": "move|scroll", "dx": int, "dy": int}
{"domain": "input",  "action": "click", "button": "left|right|middle"}
{"domain": "input",  "action": "text", "text": "<1 à 500 caractères>"}   // features.text_input ; erreur renvoyée pour les caractères impossibles
{"domain": "system", "action": "power", "kind": "suspend|reboot|poweroff"}
{"domain": "system", "action": "lock|launch", "id": "<launcher id>"}
{"domain": "system", "action": "open_media", "root": "<id du dossier>", "path": "<chemin relatif, / comme séparateur>", "opener": "<id du lecteur, facultatif>"}   // sans "opener" : premier lecteur du type ; un id inconnu ou d'un autre type est refusé
```

- `seek` est relatif, en µs. Le client l'utilise de préférence à `set_position`, qui exige un trackid valide.
- Volumes en flottants 0..1. Positions et durées MPRIS en **microsecondes**.

Serveur → client :

- `{"type":"state", "mpris":{players, active, available}, "audio":{…}, "input":{available, reason, keys, text:{available, reason}}, "system":{…}}`
- `{"type":"error","message":"…"}`
- `system.media = {roots:[{id, name}], thumbnails: bool, last: {name, type, art}|null}` : dossiers de l'onglet Médias (vide = onglet masqué côté client), miniatures disponibles (ffmpeg), dernier fichier ouvert (titre, type, URL d'image ou null) ; `last` est diffusé à l'ouverture (`SystemControl` reçoit `notify`).
- Pour un lecteur MPRIS qui joue un fichier d'une racine (`xesam:url` en `file://`), `mpris.players[].metadata` est complété côté serveur (`MediaLibrary.enrich`) : `title` = nom du fichier sans extension s'il manque, `art` = `/thumb?…&size=640` s'il manque.

### API REST des lanceurs (`admin.enabled`)

`Authorization: Bearer <jeton>` obligatoire (401 sinon) ; le jeton en paramètre d'URL est refusé. Corps JSON ≤ 16 Ko, erreurs `{"error": "…"}`.

```
GET    /api/launchers          {launchers:[{id,label,icon,kind,spec}], icons, kinds, browsers:[{id,name,installed,fullscreen}], allow_command}
POST   /api/launchers          {label, icon, kind, spec} → 201 (id généré à partir du nom)
PUT    /api/launchers/{id}     idem → 200 ; 404 si inconnu
DELETE /api/launchers/{id}     → 204
POST   /api/launchers/reorder  {ids:[…]} (tous les ids exactement une fois) → 204
GET    /api/apps               [{id: "x.desktop", name}]
GET    /admin                  page HTML (publique comme /, l'API exige le jeton)
```

`kind`/`spec` : `web` → `{url, browser, fullscreen}` ; `app` → `{desktop_id}` ; `command` → `{argv:[…]}`.
403 pour une commande brute si `admin.allow_custom_command` est faux (sauf commande existante inchangée : renommage OK).
Chaque modification déclenche `notify()` : les tablettes reçoivent la nouvelle liste (`system.launchers`, `system.admin`) sans recharger.

### API REST des médias

```
GET /api/media?root=<id>&path=<relatif>   {root, path, parent (null au sommet d'une racine), entries:[{name, kind: dir|audio|image|video, v?, size?}] (v = date du fichier en secondes, size = octets : tous les fichiers, jamais les dossiers), truncated}
                                          400 chemin invalide / hors racine / pas un dossier ; 404 racine ou dossier inconnu ; route absente si aucun dossier
GET /api/media/search?q=&root=&path=       {query, root, entries:[{name, kind, root, folder, v?, size?}], truncated} ; root absent = toutes les racines ; 400 requête < 2 caractères, > 100, > 8 mots
GET /thumb?root=&path=&size=160|320|640&token=   image/jpeg (carré recadré), Cache-Control private 1 jour ; 401 sans jeton (dans l'URL comme /art), 400 taille/chemin invalide, 404 aucune miniature ; route montée seulement si ffmpeg est présent
GET    /api/media/openers                 {openers:[{id, type, label, kind, spec}] (par type audio, image, video, puis par ordre de préférence), kinds:[default,app,command], allow_command, max_per_type}   (admin.enabled)
POST   /api/media/openers                 {type, label, kind, spec} → 201 (id généré à partir du nom) ; 404 type inconnu ; 400 nom/limite (8 par type) ; 403 commande brute sans allow_custom_command
PUT    /api/media/openers/{id}            {label?, kind, spec} → 200 ; nom absent = inchangé ; l'ancienne adresse PUT /api/media/openers/<type> marche (le lecteur implicite ou migré a pour id son type) ; 404 inconnu ; 403 commande brute
DELETE /api/media/openers/{id}            → 204 ; 400 si c'est le dernier lecteur du type
POST   /api/media/openers/reorder         {type, ids:[…]} (tous les lecteurs du type, une fois) → 204 ; le premier devient le lecteur par défaut
                                          (toute modification de lecteur est répercutée aux tablettes : `system.media.openers`)
```

`kind`/`spec` des lecteurs : `default` → `{}` (`gio open <fichier>`) ; `app` → `{desktop_id}` (`gio launch <desktop> <fichier>`) ; `command` → `{argv}` (le chemin est ajouté en **dernier argument**).

La pochette locale (`file://`) n'est jamais transmise : elle est remplacée par `/art?player=…&v=<hash>`, auquel le client ajoute le jeton.

## Décisions et raisons

- **aiohttp plutôt que Django** : un seul processus, pas de base de données ; Channels serait surdimensionné.
- **pactl plutôt que wpctl** : sortie JSON stable et `subscribe` pour les événements ; compatible pipewire-pulse.
- **uinput plutôt que xdotool/ydotool** : fonctionne sous Wayland. Deux périphériques distincts pour une bonne classification par libinput.
- **Règle udev `TAG+="uaccess"`** plutôt que le groupe `input`, qui permettrait de lire tous les claviers.
- **Saisie de texte par traduction de la disposition** (remplace l'ancien « pas de saisie de texte » : le piège était la disposition, pas la saisie). 
  Chaque caractère devient la/les touches que produirait la disposition réelle du PC : lecture de `kxkbrc` (sinon `setxkbmap -query`), index actif via `org.kde.keyboard`, 
  compilation par libxkbcommon (`ctypes`), table keysym -> (touche, Maj, AltGr), touches mortes par décomposition NFD (ê = `dead_circumflex` + e), accents isolés = touche morte + espace.
  **Pas de presse-papiers** (Ctrl+V) : Klipper garde un historique en clair, mots de passe compris, et seul le Ctrl+V fonctionne (pas dans un terminal). 
  Touches autorisées pour la saisie : `TYPING_KEYS` (bloc principal + `<>` + AltGr), contrôlées dans `VirtualInput.write_keys` ; le client ne choisit jamais un code, seulement du texte.
- **`features.text_input` désactivé par défaut** : un clavier complet donne le contrôle total du PC à qui a le jeton (Super + saisie = terminal), même logique que `allow_custom_command`. 
  Limite de 500 caractères : une trame WebSocket est limitée à 4 Ko et 500 × 4 octets (emoji) = 2 Ko ; au-delà aiohttp coupe la connexion.
- **Onglets Lecture et Son fusionnés** : le panneau `player` contient le lecteur MPRIS puis une barre de volume (sourdine, curseur du volume principal, bouton au nom de la sortie active qui ouvre la liste des sorties). Raisons : libérer un emplacement dans la barre d'onglets (4 au lieu de 5) et garder le volume à portée du lecteur. `PlayerPanel` et `AudioPanel` restent deux classes, protocole WebSocket inchangé (`domain: audio`). Un onglet `audio` mémorisé par un client retombe sur `player` (`Tabs.select`). Audio indisponible : la barre disparaît et une ligne `audio.none` la remplace.
  **Mise en page : la barre de volume doit rester visible quelle que soit la hauteur** (premier essai sous-optimal : panneau qui défile, barre sous la barre d'onglets dès ~640 px de haut, donc « masquée » sur la tablette). Donc `.panel-stack` (colonne flex, `overflow: hidden`) : le lecteur (`flex: 1 1 0; min-height: 0; overflow-y: auto`) prend la place restante et défile en interne si besoin, la barre (`z-index: 2`, la pochette est positionnée et peindrait par-dessus) est toujours en bas. Pochette carrée dimensionnée par la hauteur réellement disponible : `width: min(100%, 100cqh)` (`container-type: size` sur `.now-playing`, repli `100dvh - 330px`), désactivé en portrait où la pile est naturellement haute (`30dvh`). Liste des sorties = fenêtre flottante (`position: absolute; bottom: calc(100% + 8px)`, `max-height: 100dvh - 290px`, défilement interne) : l'ouvrir ne déplace ni ne comprime le lecteur ; fermée par le bouton, un clic extérieur ou Échap. Paliers de hauteur (`max-height: 700px` / `560px` en paysage) : bouton lecture et marges réduits, puis volume propre du lecteur et album masqués. Sur ≤ 520 px le nom de la sortie est masqué (libellé en `aria-label`). `align-items: safe center` sur la grille pour que le contenu qui dépasse reste atteignable par défilement.
- Fenêtre de saisie **non modale** (`dialog.show()`) : le pavé reste utilisable, et un `showModal()` assombrirait les toasts (hors couche supérieure).
- **Imports dbus-next par sous-modules** (`dbus_next.signature`, `dbus_next.aio.message_bus`, `dbus_next.constants`) : sinon pyright signale `reportPrivateImportUsage`.
- Les proxies dbus-next sont typés `Any`, car leurs méthodes `call_*` / `on_*` sont générées dynamiquement.
- **Page des QR codes = fichier local, jamais une route du serveur** (`make qr`, `--qr`, module `qrpage.py`) : les QR codes contiennent le jeton, une route `/qr` le donnerait à tout le LAN (même limitée à la boucle locale, elle serait fragile derrière un proxy). Page autonome écrite en 600 dans `$XDG_RUNTIME_DIR/mediadeck/access.html` (tmpfs) et ouverte en `file://` : pas de CSP à contourner (`<style>` inline permis hors serveur), pas d'avertissement de certificat, fonctionne serveur arrêté. `qrencode -t SVG` plutôt qu'une bibliothèque JS (aucune dépendance) ; le SVG reçoit `shape-rendering="crispEdges"`, sinon des lignes claires apparaissent entre les modules à l'échelle. Le jeton n'apparaît jamais en texte dans la page, seulement dans les QR codes. Le code du certificat de la CA passe par le port HTTP s'il existe (pas d'avertissement à accepter).
- **HTTPS par CA privée + `openssl`** plutôt que mkcert : aucune dépendance à installer, et la CA reçoit des `nameConstraints` (réseaux privés, `localhost`, `*.local`, `*.lan`, nom de la machine). La tablette fait confiance à cette CA : si sa clé fuitait, elle ne pourrait pas usurper un site public. Clés EC P-256, CA 10 ans, certificat serveur 825 jours (réémis sans toucher à la CA).
- **Onglet Médias** (2026-10-26) : liste les fichiers son / image / vidéo de dossiers choisis dans `config.toml` (`[media] roots`, défaut = dossiers XDG Musique/Vidéos/Images existants, jamais `$HOME` ; `[]` = désactivé) et les ouvre **sur le PC**. Chaque fichier est un « lanceur virtuel » de son type : les **lecteurs** de chaque type (`audio`, `image`, `video`, table `media_players` de la base des lanceurs, réglables sur `/admin`, voir « Plusieurs lecteurs par type ») reçoivent le chemin en dernier argument. Mêmes règles de confiance que les lanceurs : `default` (`gio open`, réglage initial) et `app` (`.desktop` choisi dans une liste) n'acceptent aucune commande du client, `command` exige `allow_custom_command`. Plusieurs lecteurs par type depuis le 2026-10-30 (voir la décision dédiée). Miniatures : voir la décision « Miniatures pour tous les fichiers ».
  **Le client n'envoie jamais de chemin absolu** : `(root, path relatif)` ; `MediaLibrary._resolve` refuse les composantes vides ou commençant par `.` (donc `..` et les fichiers cachés, aussi bien listés qu'ouverts : sinon un caché absent de la liste restait ouvrable par son nom), résout les liens (`resolve(strict=True)`). **Les liens sont suivis où qu'ils pointent** par défaut (`[media] follow_symlinks`, `MediaLibrary(follow_symlinks=…)` ; `false` = mode strict, l'ancienne règle : cible dans la racine réelle, pas de dossier relié parcouru par la recherche, pas d'image hors racine, pas de `locate` par le lien) (2026-10-26 : `~/Vidéos/Cinema -> /datadisk/datas/Videos/Cinema`, etc. ; la règle initiale « le chemin réel reste dans la racine » les rendait invisibles). Ce qui borne l'accès n'est plus la racine mais : aucun chemin absolu ni `..` ni composante cachée venant du client, liste fermée d'extensions, type pris sur le fichier réel, et les liens posés par l'utilisateur lui-même dans ses dossiers (le client ne peut pas en créer ; un lien vers `/` rendrait visibles les noms de tous les médias du disque, dans les limites de parcours). La recherche suit aussi les liens, avec un ensemble de dossiers déjà vus par racine (boucle, second lien vers le même dossier) ; ses résultats gardent le chemin logique, celui qu'on sait rouvrir. **Le lecteur reçoit le chemin de la racine, liens conservés** (`MediaLibrary.open_path`, pas `Located.real`) : il l'annonce tel quel dans `xesam:url`, ce qui permet à `locate()` de retrouver le fichier (titre, image) alors que sa cible réelle est hors de toute racine ; `locate()` essaie d'abord le chemin réel dans une racine, puis le chemin par le lien. Limite : un lecteur qui annonce le chemin réel d'une cible hors racine n'est pas enrichi (titre du lecteur ou nom du fichier, pas d'image). Les extensions autorisées sont une liste fermée (`.ts` exclu : TypeScript ; pas de `.svg`) et le type vient de l'extension du **fichier réel**, pas du lien (`lien.mp3 -> script.sh` est refusé). Parcours dans un thread (`asyncio.to_thread`), 1000 entrées renvoyées et 20000 examinées au plus, tri naturel (« 2 » avant « 10 »), noms non UTF-8 ignorés (JSON). L'ouverture passe par le WebSocket (`system` / `open_media`, comme `launch`) et `SystemControl._spawn` (session séparée) ; le listage par REST car la réponse peut être grande et le WebSocket client est limité à 4 Ko. API de listage montée seulement si au moins un dossier est configuré, **indépendamment de `admin.enabled`** (d'où `restapi.py`, helpers partagés). Un fichier de chemin de 1000 caractères tient dans la trame de 4 Ko.
- **Les commandes du lecteur ne doivent jamais sortir de la zone visible** (2026-10-26). Constat : dès ~480 px de haut en paysage (tablette avec barre de navigateur), précédent / lecture / suivant étaient coupés en bas de la zone du lecteur (elle défile en interne), et les titres de fichiers sur deux lignes aggravaient le cas. Donc : progression + commandes regroupées dans `.controls` en `position: sticky; bottom: 0` (fond opaque) : si la zone est trop basse le titre défile dessous et les boutons restent affichés. Paliers de hauteur pour que rien ne soit coupé à moitié : paysage ≤ 620 px → album et volume propre du lecteur masqués, ≤ 480 px → artiste masqué aussi ; portrait ≤ 860 px → album et volume propre masqués, pochette à 22 dvh ; portrait ≤ 700 px → pochette masquée. Pièges rencontrés : (1) un bloc collant ne peut pas dépasser le haut de son conteneur, donc sur un écran très bas la pochette doit céder la place ; (2) `grid-auto-rows: max-content` en portrait, sinon la grille écrase la ligne de la pochette (qui a `overflow: hidden`, donc un minimum automatique nul) sous le titre quand la zone est trop basse ; (3) `align-content: safe center` sur `.empty` pour que la carte « Dernier fichier ouvert » reste atteignable. Garde-fou versionné : `tests/test_ui_layout.py` (+ `tests/uidriver.py` : pilote DevTools minimal et faux serveur qui sert la **vraie** page via `render_page`/`versioned_static`) mesure dans Chromium, pour 13 tailles, que les commandes, la barre de volume et la carte sont entièrement visibles ; ignoré sans Chromium ; vérifié qu'il échoue sur l'interface d'avant la correction (commandes coupées à 960×420 et 960×480).
- **Cache de l'interface : pages revalidées, fichiers statiques versionnés** (2026-10-26). Constat : sans `Cache-Control`, un navigateur applique un cache heuristique (≈ 10 % de l'âge du fichier, soit des heures pour un fichier de 3 jours) ; une tablette affichait l'ancienne interface (Lecture et Son séparés, pas de Médias) alors que le serveur servait la nouvelle, et même un rechargement ne remplace pas les sous-ressources en cache. Donc : `Cache-Control: no-cache` par défaut (middleware `security_headers`, ETag → 304) ; `/` et `/admin` sont générés par `render_page()` qui réécrit `"/static/` en `"/static/<version>/` ; `<version>` = empreinte (chemin, taille, date) de `web/static` (`static_version()`), les imports relatifs des modules (`./common.js`) suivent le préfixe ; `/static/<version>/<fichier>` (`versioned_static`, la version n'est que dans l'URL) est servi en `public, max-age=31536000, immutable`, avec contrôle d'appartenance au dossier statique. Les anciennes adresses `/static/<fichier>` restent servies (revalidées). **Limite incompressible** : une page déjà gardée en cache par le navigateur ne peut pas être remplacée par le serveur ; ouvrir le même lien la ressert depuis le cache, une actualisation (une fois) la remplace. Vérifié par reproduction : navigateur ayant mis en cache l'ancienne version (fichiers datés de 3 jours), serveur remplacé, (a) même lien = ancienne interface, (b) Actualiser = nouvelle interface avec URL versionnées, (c) chargements suivants depuis le cache. Ne pas ajouter de `?v=` à la main dans le HTML : c'est `render_page` qui s'en charge, et le test `test_html_source_files_only_reference_static_with_a_leading_slash_quote` impose la forme `"/static/…"`.
- **Miniatures, recherche et image de l'onglet Lecture** (2026-10-26). **ffmpeg** plutôt que Pillow : déjà installé sur le PC cible, aucune dépendance Python, et un seul outil donne les quatre cas utiles (réduction d'image, image d'une vidéo, pochette intégrée d'un son ; Pillow ne fait que le premier). Optionnel : sans ffmpeg `system.media.thumbnails` est faux, `/thumb` n'est pas monté et l'interface garde ses icônes (`[media] thumbnails = false` pour désactiver). `Thumbnailer` : cache disque `$XDG_CACHE_HOME/mediadeck/thumbs` (mode 700, clé = chemin + date + taille du fichier + côté, échec mémorisé en `.none`, nettoyage à 3000 fichiers), 3 processus au plus, délai 20 s, `-nostdin -protocol_whitelist file`, images lues avec `-f image2` (un texte HLS déguisé en `.jpg` ne donne rien, testé) ; formats d'image limités à ceux que ffmpeg décode seul (HEIC/AVIF : icône). Ordre des sources : image → elle-même ; vidéo → affiche du dossier (`nom.jpg`, `nom-poster.jpg`, `poster.jpg`, `cover.jpg`, `folder.jpg`…) puis image à 5 s (repli 0 s) ; son → pochette intégrée puis image du dossier. L'image du dossier est cherchée à côté du fichier réel (qui peut être hors de la racine quand le dossier est relié) et peut elle-même être un lien ; ffmpeg ne décode qu'une image (`-f image2`), jamais un autre type de fichier. Le jeton est dans l'URL de `/thumb` comme `/art` (une balise `<img>` n'envoie pas d'en-tête) ; la version `v` (date du fichier) dans l'URL invalide le cache navigateur. Les tuiles audio et vidéo gardaient l'icône à l'origine (miniatures pour les seules images, comme demandé) ; elles ont aussi une miniature depuis le 2026-10-30 (voir « Miniatures pour tous les fichiers, et tri »).
  **Recherche** côté serveur (`MediaLibrary.search`, parcours itératif par `scandir`, pas `os.walk`, pour réutiliser `_classify` : cachés, extensions et évasions déjà filtrés) : mots sans accents ni casse, tous requis, sur le nom ; 300 résultats, 200000 entrées, 4 s ; liens non suivis (pas de boucle). Au premier niveau elle porte sur toutes les racines. Client : anti-rebond 300 ms, 2 caractères minimum, le bouton retour quitte la recherche, le filtre de type s'applique aux résultats.
  **Onglet Lecture** : titre de secours dans le client (`titleFromUrl`, nom du fichier sans extension) pour tout lecteur ; titre et image des fichiers de la bibliothèque complétés côté serveur (`enrich`) ; sans lecteur MPRIS, carte « Dernier fichier ouvert » (`system.media.last`, mémorisé à l'ouverture, perdu au redémarrage). Il n'y a pas de suivi de processus : `gio open` rend la main aussitôt, donc « dernier ouvert » et non « en cours ». Piège de mise en œuvre : un élément **SVG** n'a pas de propriété `hidden` (réservée à `HTMLElement`) : utiliser `toggleAttribute("hidden")`.
- **Miniatures pour tous les fichiers, et tri** (2026-10-30). Avant, seules les images avaient une miniature (« comme demandé ») ; le serveur savait déjà fabriquer celles des vidéos et des sons (`/thumb`), le client ne les demandait pas. Désormais `MediaPanel.tile()` demande `/thumb` pour tout fichier (pas pour un dossier) quand `system.media.thumbnails` est vrai ; **le repli sur l'icône existait déjà** (`error` de l'`<img>`), donc un son sans pochette (404, échec mémorisé en `.none` côté cache) garde son icône sans autre code. Liseré de la couleur du type sur les tuiles audio/vidéo à miniature, pour ne pas les confondre avec des images. Coût : chargement paresseux (`loading="lazy"`, donc seules les tuiles visibles), 3 ffmpeg au plus, 20 s de délai ; une vidéo sur un disque réseau (SSHFS) coûte quelques secondes la première fois, puis vient du cache. `[media] thumbnails = false` désactive tout. **Tri** : le serveur renvoie `v` (date) et `size` pour **tous les fichiers** (`MediaLibrary._stat`, un `stat` par fichier listé ; `v` ne concernait que les images), le tri nom / date (récents d'abord) / taille (gros d'abord) est fait **côté client** (`MediaPanel.visibleEntries`, ≤ 1000 entrées, tri stable donc à égalité l'ordre naturel du serveur), les dossiers restent en tête dans l'ordre du serveur, y compris dans les résultats de recherche. Choix mémorisé (`mediadeck.media_sort`, localStorage). Tests : `test_media.py` (date et taille des fichiers, pas des dossiers), `test_ui_flows.py` (`test_sort_by_date_and_size_is_remembered` : trois fichiers dont les ordres par nom, date et taille diffèrent, dossiers en tête, choix conservé après rechargement ; `ThumbnailTest` : vrai ffmpeg, une vidéo reçoit une vraie image chargée depuis `/thumb`, un son sans pochette garde son icône). Mutations vérifiées : tri ignoré, miniatures de nouveau réservées aux images. Non essayé sur la tablette ni sur votre bibliothèque réelle (vidéos SSHFS).
- **Plusieurs lecteurs par type, choisis par appui long** (2026-10-30). Avant : une ligne par type (table `media_openers`, clé = type). Maintenant `media_players` (`id`, `type`, `position`, `label`, `kind`, `spec`) : 1 à 8 lecteurs par type, nommés, **le premier (`position` 0) ouvre par défaut**, l'ordre se change sur `/admin` (↑ ↓). **Un type garde toujours un lecteur** : sans ligne, `LauncherStore.openers()` en synthétise un (`gio open`, `id` = nom du type, nom vide) ; il est enregistré (`_materialize`) dès qu'on en modifie ou ajoute un autre ; supprimer le dernier est refusé (400). **Migration** à l'ouverture de la base (`_migrate_single_openers`) : chaque ligne de l'ancienne table devient un lecteur d'`id` = son type et de nom vide, puis la table est supprimée (une version précédente ne relira donc plus ces réglages) ; l'ancienne adresse `PUT /api/media/openers/<type>` continue donc de marcher. **Choix à l'ouverture** : `open_media` accepte `opener` (id) ; absent = premier du type ; **le client ne peut désigner qu'un lecteur déjà configuré pour le type du fichier** (inconnu, d'un autre type ou non-chaîne : erreur, rien n'est lancé), la commande n'est toujours reconstruite que depuis la base. L'état diffuse `system.media.openers = {audio:[{id,label,kind}],…}` (jamais le `spec`) ; toute modification de lecteur déclenche `notify()` (avant, les tablettes n'avaient pas à le savoir). Interaction choisie par l'utilisateur : **appui = lecteur par défaut, appui long (500 ms) ou clic droit = liste « Ouvrir avec… »**, seulement si le type a plusieurs lecteurs ; pas de bouton sur les tuiles. Piège de mise en œuvre vérifié avec de **vrais événements tactiles DevTools** (`Input.dispatchTouchEvent`) : la liste s'ouvre sous le doigt et le `click` qui suit le relâchement tombe sur le fond de la feuille (qui la refermait aussitôt) ou sur un de ses boutons (qui ouvrait un lecteur par erreur) ; avec la souris le problème n'existe pas (la feuille recouvre la tuile avant le relâchement), d'où un test tactile. Donc : `MediaPanel.chooserClick` ignore les clics tant que le doigt est posé et `RELEASE_GRACE_MS` = 400 ms après ; la garde ne s'arme que si le pointeur est réellement posé à l'ouverture (clic droit Windows : le menu contextuel arrive après le relâchement) ; `data-held` empêche le `click` d'un appui long de livrer le fichier par la tuile ; `pointermove` au-delà de 10 px annule l'appui long (défilement). Étiquette d'un lecteur sans nom (implicite ou migré) : son genre (`media.player_default|app|command`). Tests : `test_launchers.py` (stockage, ordre, limite, dernier lecteur, migration de l'ancienne table), `test_admin.py` (REST), `test_integration.py` (choix par WebSocket, refus, état sans commande), `test_ui_flows.py::test_several_players_are_set_on_admin_and_chosen_by_long_press` (administration, appui bref, appui long tactile, clic de relâchement livré à la tuile, Échap, clic droit). Mutations vérifiées : serveur qui ignore ou ne valide pas le lecteur, `click` d'appui long non supprimé, garde de relâchement retirée.
- **Choix sécurisé / non sécurisé = deux écoutes simultanées** (`server.http_port`, 0 par défaut) plutôt qu'un interrupteur : la tablette choisit son adresse sans redémarrer le service, et le HTTP sert de repli quand son navigateur ignore la CA (voir Pièges). `port` garde son rôle (HTTPS dès que `tls_cert` est défini, sinon HTTP) ; `http_port` exige TLS (sans lui, `port` est déjà en HTTP) et doit différer de `port`. Les deux sites partagent **un seul `AppRunner`** (`web.run_app` ne gère pas deux ports avec des réglages TLS différents), donc la même application, la même boucle et le même jeton. Désactivé par défaut car le jeton circule alors en clair sur le LAN ; `make cert` ne l'active pas (il suggère `make http-on`) ; `make http-on [HTTP_PORT=…]` / `make http-off` appellent `--http-port N` (`tls.set_http_port` : regex sur la ligne `port`, relecture par `load_config`, fichier restauré si le résultat est invalide). Activer ce port à la main dans le TOML était trop fragile : un premier essai de l'utilisateur est resté « non concluant » faute de la ligne `http_port`. `make url` affiche deux adresses et deux QR codes ; `make firewall HTTP_PORT=…` ouvre le second port.
- La CA publique est servie sur `/ca.crt` par le serveur lui-même (route publique, uniquement si `tls_ca` est défini) : la tablette l'installe après avoir accepté l'avertissement une fois, sans second port ni pare-feu à ouvrir (la route existe aussi sur `http_port` : récupération de la CA sans avertissement, avec la même absence d'authentification qu'un avertissement accepté).
- **CSP stricte** (`script-src 'self'`, `style-src 'self'`) : aucun attribut `style=""` ni script inline dans le HTML. En JS, utiliser `el.style.setProperty()`, qui est autorisé.
- Lanceurs : uniquement des listes argv, jamais de shell, avec `start_new_session=True`.
- **Lanceurs en base SQLite** (`~/.local/share/mediadeck/launchers.db`, mode 600, module standard `sqlite3`, aucune dépendance) plutôt qu'en TOML : modifiables à chaud depuis `/admin` sans redémarrer ni éditer un fichier. Les `[[launchers]]` de `config.toml` ne servent qu'à un **import unique** (drapeau `meta.seeded`), puis sont ignorés.
- **Sécurité de l'administration** : un lanceur « commande » = exécution de code avec les droits de l'utilisateur pour quiconque a le jeton. Donc trois types : `web` (URL http(s) + navigateur d'une liste fermée) et `app` (fichier `.desktop` choisi dans une liste, lancé par `gio launch <chemin résolu côté serveur>`) n'acceptent aucune commande du client ; `command` exige `[admin] allow_custom_command = true` dans `config.toml`, fichier que le client ne peut pas modifier. La commande est reconstruite au lancement depuis la base (`build_argv`), jamais fournie par le message WebSocket.
- API REST avec jeton en **en-tête** `Authorization` (pas dans l'URL : journaux, historique) ; un en-tête personnalisé n'est pas ajoutable par un site tiers sans CORS, donc pas de CSRF.
- **Onglet Lanceurs distinct de l'onglet Système** : les lanceurs (usage fréquent, sans risque) ne côtoient plus verrouillage/veille/redémarrage/extinction (rares, destructifs, appui long), pour éviter un mauvais appui. Pur changement d'UI : le protocole WebSocket est inchangé (`system.launchers` / `system.admin` dans l'état, action `system` + `launch`). `LauncherPanel` et `SystemPanel` sont deux classes ; `tabbar` en `grid-auto-flow: column` (nombre d'onglets libre).
- `common.js` : `Storage`/`I18n`/`$` extraits d'`app.js` pour être partagés avec `admin.js` (l'`I18n` prend les messages en paramètre ; la langue choisie est commune aux pages).
- Actions d'alimentation : appui long de 1 s côté UI (`HoldButton`).

## Pièges

- Médias : sans `ffmpeg` pas de miniatures (`apt install ffmpeg`, ajouté à `make deps`) ; la première ouverture d'un dossier de grosses photos fabrique les miniatures (quelques dizaines de ms chacune, 3 à la fois), les suivantes viennent du cache. Les sources d'image des vidéos et sons dépendent des noms de fichiers du dossier (voir décisions). Le lecteur « par défaut » dépend des associations MIME de la session (`gio open`) : si une vidéo s'ouvre dans le mauvais programme, régler l'association du système ou choisir une application sur `/admin`. Une racine configurée mais absente (disque non monté) reste listée et répond « media folder unavailable » ; elle est relue à chaque requête, sans redémarrage. Les dossiers par défaut sont lus au démarrage (un dossier XDG créé ensuite demande un redémarrage). Le jeton donne accès aux **noms** des fichiers des racines.

Réglage Proton : Paramètres → Connexion → Paramètres avancés → Connexions LAN ; vérifier aussi « Bloquer les connexions sans VPN » dans les réglages VPN d'Android.

- Chromium déjà ouvert : un lanceur `web` peut s'ouvrir dans la fenêtre existante (le plein écran n'est alors pas garanti).
- `make url` détecte l'IP via la route par défaut : avec un VPN actif (WireGuard), il annonce l'IP du VPN. Renseigner `server.advertise_host` dans `config.toml` pour forcer l'adresse du QR code **et du certificat** : `make cert` émet le certificat pour l'adresse annoncée (`tls.default_hosts`), donc `advertise_host` se règle **avant** `make cert` (sinon corriger puis relancer `make cert`, la CA ne change pas). Vu en vrai : `make url` annonçait `10.2.0.2` (tunnel WireGuard de Proton VPN) sur le PC de l'auteur. Signalé dans l'installation des README et dans `config.example.toml`. **Avertissement automatique** (2026-10-30, `network.py`, `warn_if_virtual` appelée par `make url`, `make qr`, `make cert`) : si l'adresse a été *détectée* (ni `advertise_host` ni `host` explicites) et appartient à une interface sous `/sys/devices/virtual` (wireguard, tun, pont, veth), un message sur stderr propose les adresses des interfaces réelles. Pas de `ip`/`psutil` : `ioctl(SIOCGIFADDR)` par interface. Vérifié ici (route par défaut par `wg-FR-9` → avertissement avec `192.168.1.34 (wlp7s0)`, silencieux avec `advertise_host`) ; `tests/test_network.py`. Limite : l'avertissement n'empêche rien et ne choisit pas l'adresse à la place de l'utilisateur.
- `firefox --kiosk` (et `chromium --kiosk`) ignore F11 : impossible de quitter le plein écran depuis la télécommande. Le lanceur YouTube TV utilise `chromium --start-fullscreen`, que F11 permet de quitter.
- Lancé hors session graphique (ssh, cron), il n'y a pas de bus de session : MPRIS et système sont désactivés (log d'erreur) mais le serveur démarre quand même.
- `/dev/uinput` nécessite `modprobe uinput` et une reconnexion de session après `make uinput` ; vérifier avec `getfacl /dev/uinput`.
- **« Je n'ai plus les commandes du lecteur » a plusieurs causes très différentes** : (1) commandes coupées par la hauteur de fenêtre (voir la décision sur la mise en page ; garde-fou `tests/test_ui_layout.py`) ; (2) **aucun lecteur détecté** : l'onglet Lecture montre alors la vue vide (icône ou carte « Dernier fichier ouvert ») et jamais de commandes, alors que la barre de volume, indépendante (PipeWire), reste là. Pour trancher, interroger le serveur en direct (`/ws`, section `mpris.players`), le comparer à `busctl --user list | grep mpris`, et lire les lignes `MPRIS player added/removed` et `cannot attach MPRIS player …` du terminal de `make run`. Quatre causes du second cas ont été trouvées, aucune n'était visible dans l'interface :
    - **Introspection vide (Chromium, Brave)** : ils répondent aux propriétés et aux méthodes MPRIS mais `Introspect` renvoie `<node></node>` ; dbus-next ne pouvait donc pas construire de proxy (« interface not found on this object ») et aucune vidéo de navigateur n'apparaissait. Correctif : les interfaces MPRIS sont décrites en statique (`_INTROSPECTION`, spécification MPRIS 2) et jamais lues chez le lecteur. À ne pas remplacer par l'introspection du lecteur.
    - **Nom pris avant les objets, ou lecteur occupé** : un lecteur peut prendre son nom de bus bien avant de répondre (objets exportés plus tard ; Celluloid qui ouvre un fichier de 400 Mo lu par SSHFS dans `~/Vidéos/miraceti`, alors que Dragon Player répond en 1 s). Un seul essai à +0,3 s, puis huit secondes d'essais, l'écartaient pour toujours. `_add` réessaie maintenant **tant que le lecteur reste sur le bus** (`ATTACH_PAUSES`, puis `RETRY_EVERY` = 3 s ; chaque tentative limitée à `ATTACH_TIMEOUT` = 5 s), annulé quand le nom quitte le bus ou change de propriétaire ; un seul avertissement (« does not answer yet … still trying ») après les premières tentatives. `MprisManager.stop()` annule tout à l'arrêt du serveur.
    - **Lecteur relancé sous le même nom** : les noms sont fixes (`dragonplayer`, `io.github.celluloid_player.Celluloid.instance-1`, `brave.instance<pid>`…). L'ancien objet `Player` restait abonné à `PropertiesChanged` (dbus-next compare l'expéditeur au propriétaire *courant* du nom, pas à l'instance du proxy) ; le signal du nouveau lecteur appelait `_schedule(name, …)` qui **annulait l'ajout en attente**, sans message. Correctif : `Player.close()` (appelé par `_remove` et si la lecture initiale échoue) retire les abonnements (`off_properties_changed`, `off_seeked`). À retenir : tout abonnement à un signal D-Bus par nom bien connu se retire à la disparition du nom.
    - **Signal reçu pendant une tentative de rattachement** (2026-10-30, trouvé par un test instable, ~1 échec sur 8) : chaque tentative s'abonne à `PropertiesChanged` avant sa lecture initiale ; un signal du lecteur pendant cette lecture appelait `_schedule(name, …)`, qui annule la tâche d'ajout en attente… c'est-à-dire celle qui exécute la tentative, et la remplaçait par un `_refresh` d'un objet jamais inscrit : lecteur jamais listé, plus aucun essai. Même famille que le cas précédent, mais touche aussi un lecteur qui n'a jamais été relancé (un lecteur lent qui publie ses objets puis annonce aussitôt ses propriétés). Correctif : le gestionnaire de signal n'agit que si `self._players.get(name) is player` (lecteur inscrit) ; sinon la lecture initiale de la tentative voit déjà le changement. Test déterministe : `test_signal_during_an_attach_attempt_does_not_cancel_the_attach` (première lecture bloquée par un `asyncio.Event`, signal émis, puis libérée ; échoue sans le correctif). Fenêtre résiduelle négligée : un changement entre la réponse de la lecture initiale et l'inscription (même tour de boucle). À retenir : un gestionnaire de signal ne doit jamais appeler `_schedule(name, …)` pour un objet dont l'ajout est encore en cours.
    Méthode qui a fonctionné : reproduire avec les **vraies applications par défaut** de l'utilisateur et un navigateur réel (profil jetable : `brave-browser --user-data-dir=… --autoplay-policy=no-user-gesture-required page.html`) face à une instance isolée du serveur sur le vrai bus de session (autres ports, config sans saisie), et instrumenter le gestionnaire ; un faux lecteur bien élevé masquait les trois défauts. Ne jamais lancer de médias sur le bureau de l'utilisateur pendant qu'il teste : fermer chaque lecteur lancé par `org.mpris.MediaPlayer2.Quit`.
- **Brave (comme Chromium) ne publie un lecteur MPRIS que lorsqu'un média joue du son** : constaté avec Brave 156, aucun nom `org.mpris.MediaPlayer2.brave.instance<pid>` sur le bus tant qu'aucun flux audio n'existe (`pactl list sink-inputs`), puis le nom apparaît et le serveur le liste. Une page dont la vidéo ne démarre pas (arte.tv, probablement protégée par DRM) ne crée donc aucun lecteur : ce n'est pas un défaut de MediaDeck. Chromium et Firefox vérifiés de même par l'utilisateur.
- **Bouton « Clavier » grisé** (vu sur une installation neuve, 2026-10-26) : `features.text_input` est faux par défaut (volontaire, voir la décision), et `make config` ne l'active pas. L'interface le grise (`aria-disabled`, pas `disabled`, pour que l'appui reste possible) ; **un appui affiche la raison dans un toast** (une infobulle `title` est invisible sur tablette) et le serveur journalise `text entry enabled` / `text entry unavailable: <raison>` au démarrage. Raisons : `disabled in config (features.text_input)`, `cannot open /dev/uinput … (run 'make uinput')` (reconnexion de session nécessaire), `libxkbcommon not found`, `python3-evdev not installed`. Test : `tests/test_ui_text_button.py`.
- **« Votre connexion n'est pas privée » sur la tablette** (Pixel 8, 2026-10-26). Trois causes, à tester dans cet ordre : (1) **certificat émis pour la mauvaise adresse** : sur le Slimbook (`192.168.1.25`), `openssl s_client -connect <ip>:8765 | openssl x509 -noout -ext subjectAltName` donnait `IP Address:10.2.0.2` (tunnel WireGuard de Proton VPN) parce que `advertise_host` n'était pas renseigné avant `make cert` ; correctif : `advertise_host = "192.168.1.25"`, `make cert` (même CA), redémarrer le service (`NET::ERR_CERT_COMMON_NAME_INVALID`). Un serveur joignable se sonde en lecture seule depuis un autre poste de la même façon, sans jeton. (2) **CA non installée** sur l'appareil (`NET::ERR_CERT_AUTHORITY_INVALID`) ; chaque machine a **sa propre CA** (`MediaDeck local CA <nom de la machine>`) : celle du PC fixe ne couvre pas le Slimbook ; téléchargement sans avertissement par le port HTTP (`http://<ip>:8766/ca.crt`, `Content-Type: application/x-x509-ca-cert`). (3) **Autre adresse du PC** que celle du certificat (PC fixe : câble `192.168.1.104` annoncé, Wi-Fi `192.168.1.13` non couvert ; `curl --cacert` échoue). Un message de certificat prouve que le réseau passe (un VPN bloquant le LAN donnerait un délai d'attente, pas ce message). Non vérifié avec le moteur de Chrome ni sur le téléphone (`certutil` absent ici). Fait : `make cert` / `make url` / `make qr` avertissent quand l'adresse détectée est sur une interface virtuelle (voir le piège `make url` ci-dessus). Ne couvre pas la cause (3) : une adresse réelle autre que celle du certificat.
- Les navigateurs exposent souvent MPRIS sans `Volume` / `Shuffle` / `LoopStatus` : l'UI masque ces contrôles quand la valeur est `null`.
- La position MPRIS n'est pas signalée par `PropertiesChanged` : elle est relue explicitement (`refresh_position`).
